# 简历项目演示指南

项目定位：个人练习项目，演示门店“茸茸星球”，不正式经营。地址、个体健康记录、检疫材料与协议均为模拟内容。线上预约不扣款；演示中的“已收款”仅记录测试状态，不代表真实付款。

## 两个环境

| 环境 | 入口 | 身份与外部服务 |
| --- | --- | --- |
| 原本机项目 | `http://127.0.0.1:8090/`、`/admin/` | 原账号、真实阿里云图形认证；保留现有服务配置 |
| 隔离演示副本 | `http://127.0.0.1:8190/`、`/admin/` | 独立数据库、Redis、Nacos 与上传卷；模拟图形认证和短信，禁用 OSS、微信及 DeepSeek 外部调用 |

隔离副本使用真实 Nginx、Gateway、两个 Java 业务服务和 Feign 转发。图形认证替代实现只存在测试辅助 JAR 中，不进入生产包；浏览器脚本只在副本公开配置返回 `demo-acceptance-only` 时注入模拟 SDK。

## 建议讲解顺序

1. 浏览宠物、按猫狗或价格筛选；进入示例详情，展示疫苗、驱虫、检疫水印与编号。
2. 买家登录，选择可预约宠物，阅读模拟协议，填写未来七天内 08:00-17:00 的到店时间。联系人填写“模拟买家”，电话填写上述测试号码。
3. 提交后展示预约待确认及库存占用；后台进入订单详情，点击“确认到店预约”。
4. 后台点击“已到店付款并交付”，确认模拟收款与检疫核验。买家刷新状态，展示订单完成、宠物已售，以及订单协议/门店快照。
5. 切换到买家“我的预约”中的 `DEMO-AFTERSALE-20261009` 历史夹具，申请健康问题售后，上传 `output/demo-materials/diagnosis-demo.png`。诊断时间选择当前时间，处于夹具保障期内。
6. 后台“售后管理”查看材料，通过授权临时链接打开诊断附件，填写模拟审核意见并选择“驳回并说明原因”。买家刷新展示审核进度。这个分支验证记录与权限，不发生退款。

新建到店预约交付后不开放在线售后，需联系门店线下处理。第五步使用独立历史订单，不能把两条链路讲成同一笔订单的功能。退款和换宠代码保留历史兼容范围，不作为新预约支付能力宣传。

## 自动验收与证据

在干净副本中运行以下命令，会创建一次演示预约并处理一次历史售后：

```sh
node scripts/demo-browser.cjs
```

脚本只允许本机非 8090 端口并检查模拟配置标记。结果保存在 `output/demo-acceptance/report.json`，截图在同一目录。重复完整验收请新建干净副本：上一轮已经售出的宠物不能再次预约，已审核的历史申请也不能再次创建。

核心解释材料：Java 使用单宠唯一占用、业务事务与幂等键；订单保存商品、门店和协议快照；公开检疫图片与私有诊断材料采用不同访问规则；通知进入事务 outbox；AI 使用 DeepSeek API 与 RAG，没有模型微调。未进行生产压测，不编造吞吐量或高并发成绩。
