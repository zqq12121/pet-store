# 灵宠小珠 · 原生微信小程序

采用 WXML / WXSS / JavaScript，无 npm 运行依赖。当前启用首页、选宠、动物详情、收藏、我的、微信登录，以及网站扫码确认，共 7 个页面，以 `app.json` 为准。

网站扫码确认是用户要求的中转功能：扫码打开灵宠小珠，微信登录后核对电脑上的核对码并主动确认，电脑网页自动登录。详见 [中转登录说明](../docs/MINI_WECHAT_QR_LOGIN.md)。演示模式不批准网站登录。

## 导入与演示

微信开发者工具 → 小程序 → 导入 → 选择本目录 `mini-program/`。此工作区已填写小程序 AppID；复制到其他工作区时使用自己的 AppID，不要在小程序包内填写 AppSecret。

`config.js` 默认 `demo: true`，页面明确标注本地演示。流程：浏览动物 → 按名字、品种、分类或价格筛选 → 查看详情与成长档案 → 收藏 → 阅读隐私说明并点击“演示微信登录” → 返回原页面 → 再次点击收藏 → 在收藏页查看或取消。

登录无需手机号或验证码。演示模式不调用真实微信登录，使用本机稳定的模拟身份；演示收藏只保存在本机缓存。退出后重新登录同一模拟身份可以找回本机收藏，但不能据此证明跨设备同步。

预约、预约记录、养宠助手和门店指南已从页面注册和打包配置中排除，旧源码仅保留供历史参考。网站自身的预约等功能不受影响。

## 真实接口联调

编辑 `config.js`：

```js
// 仅在服务端和微信合法域名均配置完成后切换真实模式。
module.exports = {
  demo: false,
  apiBase: 'https://你的域名/api/v1',
  assetOrigin: 'https://你的域名'
}
```

| 功能 | 接口 |
| --- | --- |
| 首页、选宠、详情 | `GET /home`、`GET /pets`、`GET /pets/{id}` |
| 微信登录 | `POST /auth/mini-wechat/login`，请求体仅含 `code` |
| 收藏列表、收藏状态 | `GET /me/favorites`、`GET /me/favorites/{petId}` |
| 收藏或取消 | `PUT /me/favorites/{petId}`，请求体为 `{ "active": true }` 或 `{ "active": false }` |
| 我的、退出 | `GET /me`、`POST /auth/logout` |

真实登录只在用户点击后调用 `wx.login`，由服务端交换微信凭证。Java 对首次通过校验的微信身份自动注册，老用户复用原账号，并返回 `isNewUser`；登录页显示对应成功提示。接口和验证边界见 [微信登录说明](../docs/MINI_WECHAT_LOGIN.md)。服务端需配置 `PAW_WECHAT_MINI_APP_ID` 和 `PAW_WECHAT_MINI_APP_SECRET`，AppSecret 仅留在服务端。小程序凭证与网站扫码登录凭证分别配置。

后端继续使用项目现有 Java 服务与 MySQL，收藏归属由登录会话决定，不接收客户端指定的账号 ID。已有数据库需先备份，再检查并应用 `backend/deploy/pet-favorites-migration.sql`；不要通过重跑完整 `schema.sql` 更新已有数据库。真实模式收藏保存到服务端账号，跨设备同步仍需真实微信登录和两台设备验证。

微信后台需配置 HTTPS request 合法域名，并按资源实际来源配置图片下载域名。当前流程不使用短信认证网页或 web-view，无需为这套登录流程配置旧 `mini-captcha.html` 桥接。

请求失败不会回退演示数据。接口返回空内容或非 JSON 错误时会显示可重试错误；登录失效会清除本机会话，收藏页和“我的”页会清空旧账号内容并显示登录入口。下架动物仍可在收藏列表取消收藏。
