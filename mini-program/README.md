# 茸茸星球 · 原生微信小程序

按 2026-10-11 上午保存的 Figma 页面、节点报告与原始照片开发，采用 WXML / WXSS / JavaScript，无 npm 运行依赖。
## 导入与演示

微信开发者工具 → 小程序 → 导入 → 选择本目录 `mini-program/`。此工作区已由用户填写小程序 AppID，调试期间保留原配置；复制到其他工作区时确认使用自己的 AppID。

`config.js` 默认 `demo: true`，页面明确标注本地演示。用任意符合格式的练习手机号点击获取验证码，填 `123456` 登录。短信、预约和 AI 均不调用真实服务；预约仅保存在本机缓存，不写现有数据库。不要输入他人手机号。

流程：选宠 → 详情 → 到店预约 → 手机号登录 → 填联系人、同一手机号与未来 7 天的营业时间 → 阅读并同意须知 → 提交 → 我的预约 → 详情／取消／到店指南。每个演示账号限一个有效预约；取消后可重新演示其他宠物。不同账号的预约隔离。

上午的 33 张设计状态合并为 11 个业务页面和 1 个认证桥接页面。猫咪、狗狗、2 千元以内、不同宠物的完整预约链以及无预约状态通过动态数据呈现。微信顶部导航、胶囊、状态栏与底部安全区由原生系统绘制，不复制原型里的假系统栏。

## 真实接口联调

编辑 `config.js`：

```js
module.exports = {
  demo: false,
  apiBase: 'https://你的域名/api/v1',
  assetOrigin: 'https://你的域名',
  captchaPage: 'https://你的域名/mini-captcha.html'
}
```

小程序只使用现有接口，没有修改后端认证、库存、订单或数据库。请求失败会保留错误和表单，不回退演示模式。配置中不要填写 AppSecret、阿里云 appKey 或其他服务端密钥。

| 功能 | 现有接口 |
| --- | --- |
| 首页、选宠、详情、门店 | `GET /home`、`/pets`、`/pets/{id}`、`/shop` |
| 登录 | `GET /auth/graph-captcha`、`POST /auth/sms-codes`、`/auth/sms-login` |
| 预约 | `POST /orders/preview`、`GET /agreements/current`、`POST /orders` |
| 记录与取消 | `GET /orders`、`/orders/{id}`、`POST /orders/{id}/cancel` |
| 我的 | `GET /me`、`POST /auth/logout` |
| 养宠助手 | `POST /guest-sessions`、`POST /ai/sessions`、`POST /ai/sessions/{id}/messages` |

登录保留阿里云服务端二次校验。点击获取验证码才打开 `web-view`；认证网页通过 `postMessage` 传回四个官方凭据，用户点返回后小程序发送短信。网页不接收手机号、会话 token 或密钥。取消图形认证不会发送短信。**这套桥接已实现并做逻辑测试，尚未在手机上通过真实认证验收。**

认证网页位于 `frontend/public/mini-captcha.html`，现有 Vite 构建会将它加入网站。微信后台需要配置 request 合法域名、图片所在域名及 web-view 业务域名，并按微信要求放置域名校验文件。主体是否支持 web-view 以微信后台实际权限为准；不支持时需另接官方原生认证能力，不能去掉服务端图形校验。原网站的微信 OAuth 不是小程序 `wx.login`，首版沿用手机号短信登录。

AI 首版通过 `wx.request` 接收完整 SSE 文本，回复完成后展示正文、来源、宠物及本人预约卡片；暂不逐字显示。断线重试复用同一 `clientMessageId`，服务端失败不显示成功回答。

门店电话、微信和坐标为空时隐藏对应操作。线上只预约，不收款；练习地址、模拟宠物资料和 DEMO 标识均保留。

## 验证

从项目根目录执行：

```sh
npm --prefix mini-program run check
npm --prefix mini-program test
git diff --check
```

检查脚本验证页面注册、JavaScript、JSON、导航资源；本机安装微信开发者工具时调用其真实 `wcc` 与 `wcsc` 编译器。测试覆盖预约、本人手机号、协议版本、重复提交、账号隔离、取消接口摘要、筛选竞态、401、网络失败与 SSE 异常。

2026-10-11：14 个 WXML、15 个 WXSS 文件通过本机编译器；8 项核心与页面逻辑回归通过。4 张照片与设计原始资产 SHA-256 一致。用实际页面 JavaScript 与 Node 请求适配只读验证现有 `127.0.0.1:8090` 后端：首页推荐 4 只、选宠第一页 12／20 只、独立详情及门店字段均兼容，空电话／微信／坐标入口正确隐藏；此检查不包含原生 UI 渲染或真实预约写入。

初次交付时因服务端口关闭而未完成模拟器验收。2026-10-11 后续调试已在用户授权开启端口后完成：原生模拟器覆盖 11 个业务页面，演示登录 → 返回原宠物预约 → 提交 → 记录／详情 → 取消链路通过；分类、价格、搜索与空状态通过，四只宠物详情和预约表单的 ID 一致。修复登录返回参数未解码、v2 按钮默认宽度造成的溢出／窄入口、长预约号挤压状态，以及编译产物被编辑器误报为源码错误的问题。新增登录返回参数回归，现共 9 项测试通过。

模拟器测试使用本地演示数据；复选框、日期／时间选择器与搜索清空通过对应事件验证，取消确认弹窗采用临时 mock 并恢复。自定义宠物卡片跨组件选择器受工具限制，验证其 `open` 方法与详情／预约按钮链路，未覆盖卡片内部真实触摸。**手机图形认证、真实短信送达、真实预约写入、公网域名和真机仍未验收。** 本机模拟器通过不等于真机验收通过。
